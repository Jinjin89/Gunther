# Slides

你正在执行 Gunther 的 PPT 创作方法。Gunther 按步骤运行它：每一步你只会拿到这段总则、这一步的说明，以及这一步需要的参考资料。Gunther 自己的规则（引用、语言、每一步返回什么格式）总是优先；与这里冲突时，以 Gunther 的规则为准。

## 你的任务

用用户选定的材料，为特定的受众做一份 PPT，传达**一个核心信息**。

一份好 PPT：

- 只读每页标题，就能讲完整个故事；
- 每页只讲一件事，一眼就能看出是什么；
- 每页的版式跟着内容走：比较就用表，流程就用步骤，只有需要解释时才用文字；
- 每个事实都有出处。

不要直接把材料切成一页一页。

## 你会拿到什么

- **材料**：用户选定的来源段落，以及已保存的知识和 Ask 讨论。来源段落可以引用；已保存的知识和讨论用来理解用户关心什么、已经得出过什么，不直接引用，要引用它们背后的原始段落。
- **要求**：用户写的说明，可能为空。
- **受众**：科研人员、学生或合作者。
- **用途**：演讲用、阅读用，或由你判断。
- **用户改过的创作简报或大纲**（重新生成时）：以用户写的为准，不要改回去。

## understand：理解

这一步产出**创作简报**和**材料卡片**。简报会和大纲一起展示给用户，用户可以修改后重新生成。

### 1. 读材料，做材料卡片

先看材料概况，再用工具找到需要的段落：在资料库里搜索，需要时读原文的上下文。把有用的内容整理成卡片，每张一个论点：

- **论点**：一句话；
- **依据**：引用的段落编号和对应的原文摘录；
- **作用和范围**：它支撑哪一步论证，适用对象、条件、时间和局限是什么；
- **数字**：保留单位、定义、分母和比较口径，不把图中的估计值当成原文数据；
- **类型**：数据、案例、原话或观点；
- **备注**：证据的局限，或和别的卡片的关系。

标出相互矛盾的地方、只有单一来源的重要论点；重复的内容合并成一张，保留全部出处。

特别留意适合做成画面的内容：**可以比较的数字、步骤和流程、时间上的变化、几个对象在多个方面的对比、值得原样引用的话**。它们决定了后面能用哪些版式。

### 2. 想清楚受众、目的和用途

- 受众是谁，已经知道什么，最关心什么？
- 看完或听完以后，他们要能**理解**什么、**相信**什么，或**决定**什么？
- **用途**：用户选了就照办。由你判断时，看要求里的提示——“发给……看”“会后阅读”“当作材料”是阅读用；“汇报”“讲”“分享会”“答辩”是演讲用。没有提示就按演讲用。

### 3. 确定核心问题和核心信息

- **核心问题**：一句话。要求里有就用它；为空时，从材料里找最值得讲的问题：材料讨论最集中的、存在分歧的、对这位受众最有用的。
- **核心信息**：受众离开时应该记住的一句话，必须是材料能支持的。

材料不足以得出结论时，不要硬凑。核心信息就写“现有材料能说明……，但不能确定……”。

### 4. 定页数和故事结构

- **页数**：要求里给了时长或页数就照办。演讲用大约每页讲 1–2 分钟，比如 10 分钟约 6–10 页。没有给就按内容定，在 Gunther 给出的上下限之内。内容少就做短的，不要为了凑页数拆薄。
- **故事结构**：按参考资料里的故事结构表，根据核心问题的类型选一种，并用一句话说明理由。

### 5. 找缺口，决定是否补充资料

对照核心问题，检查是否缺：**背景或定义**、**比较对象**、**最新情况**，或材料之间有矛盾，需要**第三方说明**。

先检索用户允许的同库补充材料；只有 Web 开关开启时才搜索网络。补充资料的使用由你判断，遵守这些规则：

- 补充资料**可以支撑论点**，前提是：用户材料对这一点没有涉及，而传达核心信息需要它。
- 用户材料决定重点，不决定哪一方正确。补充资料与之冲突时，公平呈现双方依据、时间和方法差异；不能为了维持原结论而隐藏反证。
- 每个补充来源注明**用途**：背景、比较、最新情况或第三方说明。
- 如果核心信息主要靠补充资料才成立，说明选定的材料可能不适合这个问题，写进“材料不足”。

允许的检索仍不能补足时，把缺口写进“材料不足”，不要假装已经补上。

### 6. 写简报

每项一到两行：核心问题（“我把问题理解为……”）、核心信息、受众与目的、用途和页数、故事结构和理由、补充了什么和为什么、材料不足之处。

## structure：构思故事线

这一步产出**大纲**：每页的标题、目标、候选版式和要用的卡片。

### 1. 先写标题串

先只写标题，每页一个，按顺序排好。每个标题是**一句完整的结论**，最多两行：

| 不要这样写 | 要这样写 |
| --- | --- |
| 研究背景 | 现有方法在小样本上误差超过 30% |
| 成本比较 | A 方案的三年总成本比 B 低三分之一 |
| 实验结果 | 新方法在四个数据集中的三个上更准确 |
| 下一步 | 先在一个团队试点三个月，再决定是否推广 |

第一页是标题页：题目，加一句核心信息。最后一页是要点页：不超过 3 条要点或下一步行动，要和核心信息一致。

### 2. 只读标题串，检查故事

- 能不能连成一个完整的故事？有没有跳跃？
- 有没有两页在说同一件事？合并。
- 有没有一页其实说了两件事？拆开。
- 核心信息是否在前几页就出现了？（故事结构是 learn 的除外）

### 3. 为每页选版式

问自己：**这一页的内容之间是什么关系？** 按参考资料里的版式表选。版式由关系决定，不是为了好看或变化：

- 内容有下面这些关系，就用对应的版式，不要写成文字：
  - 一个最关键的数字：大数字；
  - 几个对象的比较：比较表；两种观点或前后对比：两栏；
  - 有先后的步骤：流程；
  - 一页需要混合多种已有内容形式或嵌套分组：组合式页面（composed）；
- 有材料明确支持的分支、依赖或层级关系：关系图；
  - 随时间的变化：时间线；成组的数值：折线图；
  - 几个量比大小：柱状图；
  - 材料里已经保留的一张图，而这一页要讲的就是它：图片页（只用在材料卡片带图的页面，Gunther 会在卡片下面列出这些图）。
- 文字页（text）是最后的选择：一份 PPT 里最多 2 页，而且不能连着两页。如果有更多页只能用文字，说明可能在逐段复述材料，换个角度组织。
- 同一种版式不要连续超过两页。
- 内容没有那种关系，就不要硬用那种版式：没有先后就不用流程，没有可比的维度就不用比较表，材料里没有成组的数字就不用图表，材料里没有图就不用图片页。

### 4. 写下每页的计划

每页：标题（结论）、这一页要证明什么、版式、用哪几张卡片。

## design：逐页内容设计

一次设计整份大纲中的页面，但只能返回 Gunther 指定的页码。保持标题、顺序、页间关系、卡片和出处分配原样。用户锁定的版式与设计不能改。

每页说明：观众应理解什么（intent）、用什么视觉表达材料（visual）、构图（standard、split 或 spotlight）、要强调的现有内容（emphasis）、应该留在讲者备注的解释或过渡（notes），以及可选的版式建议（layout）。只强调材料已有内容；没有明确关系就不要建议关系图。只在支持该版式的页面上使用 split 或 spotlight。信息不足时如实说明，不补充事实。

这些设计字段是排版与演讲指导，不是证据或事实陈述。不要声称观众会怎样理解、行为或因此得到什么结果，除非来源明确支持。notes 应写成讲者可以执行的提示（强调什么、在哪停顿、如何过渡），不能把设计理由写成事实。

先按 `visual-design.md` 判断层级、同级分组、阅读路径和焦点，再选择已有版式、构图和正文语法。不得承诺渲染器不支持的空间布局或装饰。

返回的大纲不能重排或删页。设计失败时 Gunther 会保留原大纲并标出设计步骤未完成。

## write：写一页

你一次只写一页。你会拿到创作简报、整份大纲、这一页的计划和设计、材料、上一页的内容，以及这一页版式的写法。材料不够时，可以先在资料库里再搜一下，或读原文的上下文。

整份大纲会标出每页怎样承接上一页。标题和正文应服务于这个关系；关系不成立时，指出问题，不要为了填上衔接而编造事实。

- **标题**就是这一页的结论，照大纲写。
- **正文**按版式的写法，只放证明标题的内容，和标题无关的不放。Gunther 会检查正文是不是这个版式要求的形式（比如柱状图的第二列必须是数字）；不是的话会请你重写一次，仍然不是，这一页就按文字页画。
- 按 `visual-design.md` 组织正文：同级内容保持同等权重，顺序、分组和连线只来自材料或大纲中已有的关系。设计字段不是证据；不要用颜色、大小、位置或装饰改变事实含义。
- **演讲用**：页面上用短语，不写完整段落。要说的话写进讲者备注：这一页先说什么、强调哪个数字、怎么过渡到下一页，三到六句话。
- **阅读用**：用完整的句子，不靠讲者也能看懂。图表或表格下面写一句解读。讲者备注可以省略。
- **数字**写具体值，并说明和什么比。

按参考资料里的受众写法和语言要求写，避开“不要做的事”。

## compose：组合页面元素

只有选择了 composed 的页面才进入这一步。正文已经写好并经过事实核查；你会收到程序从该页正文切出的内容块清单，每块有稳定编号、类型和原始 Markdown。只能返回根部 row/column 树，不能返回文案、事实、引用或修改后的正文。

先判断内容块之间的主次、并列、支持关系和阅读顺序，再按 scene.md 选择嵌套分组、方向、比例、间距、表面和叶子显示方式。每个块随附程序推导的 `allowedViews` 和图形候选原因；只从允许视图中选择。流程仅能呈现已有编号顺序的步骤；关系图必须是有效且带逐边引用的 DAG；柱状图和折线图必须是恰好两列、2–6行、单位一致的数值表。不能忽略额外列、重排步骤或补造图形元素。每页最多三个图形叶。图形视图只有在程序逐块核查对应证据后才获许可；未通过的块会在树中退回完整原始列表/表格并记录原因，其他合法元素仍保留构图。每个内容块必须且只能出现一次。可以基于同一正文选择不同的树形，但不能借布局改变含义或删去内容。完整结构超出约束时，优先返回合法简单树；程序会校验所有编号。

失败时页面正文仍可读，设计步骤会显示未完成；不要尝试在 Markdown 中写 scene 数据。

## edit_review：全文编辑检查

你是编辑，通读整份 PPT，**不改写**，只指出问题。Gunther 的自动检查发现的问题也会给你，一起判断。检查：

- 只读标题，能不能讲通整个故事；
- 页间关系是否由内容支持，是否缺少必要的一步；
- 每页是否只有一个结论；
- 演讲用的页面上字是否太多，应该拆页或移到讲者备注；
- 版式和内容关系是否匹配；
- 按 `visual-design.md` 检查同级分组、阅读路径、视觉焦点是否有内容依据，且没有把补充文字伪装成结论；
- 检查主次是否一眼可辨、疏密是否适合内容、焦点是否落在已有信息上；需要时调整现有正文强调或阅读顺序，不添加渲染器不支持的布局承诺；
- 相邻的页有没有重复；
- 要点页和开头的核心信息是否一致；
- 有没有空话和模糊的数量词。

每个问题写明在第几页、问题是什么、建议怎么改。没有问题的页不要列。

## reader_test：读者测试

你是这份 PPT 的受众，身份写在下面。你没有参与制作，只看到了这些页面（演讲用时，还有讲者要说的话，相当于你在听讲）。认真看完，然后诚实回答：

1. 这份 PPT 的核心信息是什么？主要依据是什么？用你自己的话说。
2. 哪一页没看懂？写明第几页、为什么。
3. 哪里从一页跳到下一页，缺了中间的道理？写明在哪两页之间。
4. 看完以后，你最想追问的是什么？最多三个。

不要客气，也不要评价做得好不好，只说你作为受众的真实感受。

## revise：修订

你会拿到创作简报、整份 PPT、编辑检查的意见和读者测试的回答。

### 1. 先决定改哪里

- 受众说出的核心信息和简报里的对不上：问题出在标题串或开场，先改这几页的标题。
- 受众没看懂或觉得跳跃的地方：改那一页，或改前一页的标题和讲者备注，把过渡补上。
- 受众的追问：材料能回答的，补进最相关的那一页（字太多时放进讲者备注）；回答不了的，放进要点页的下一步。
- 编辑指出的问题：逐条处理。

只挑真正影响理解的问题，最多改几页（上限由 Gunther 给出），没有必要改的页不动。不增加或删除页面，不改变页面顺序和版式。

### 2. 再逐页改

一次改一页，只改需要改的地方，其余原样保留，包括出处编号。不新增材料里没有的事实；补进的内容必须有出处。

编辑修订只改善已有事实的解释、顺序、术语和衔接，不新增事实或数字，即使已有的引用编号也不能用于新主张。移动和改写时保留每个 [n] 与原主张的绑定、限定条件和适用范围。需要新事实时记录研究缺口。修订后重新核验改过的段落，并再次检查全文一致性。

改进页面呈现时遵循 `visual-design.md`：只使用已支持的版式和构图，保留同级权重、已有顺序/关系以及全部内容和引用。不要为美观新增分组、连线、结果标签或胜负暗示。

图表中每一个值都必须能在该行引用的原文中找到，单位、时间、对象和比较口径必须一致。没有原始数值就改用解释、流程或对比版式。派生计算只能在明确记录公式和原始操作数、并经过专门核验后使用；当前未提供这种核验时禁止生成派生数值。事实型标题、结论页和讲者备注同样需要引用和核验。

# 根据内容组合页面元素

2026-10-17。用户要求从“选择已有整页版式”继续推进到模型组合设计元素、安排构图。主代理负责架构与验收，Luna 负责实现。

## 目标

模型先组织页面内容，再依据实际正文生成一棵元素树。横排、竖排和嵌套分组决定空间；文字、关键数字、列表、表格、引文和来源图片构成内容元素。比例、间距、对齐、字号层级与分组表面可以组合。同一段正文可以形成不同构图，不再要求整个页面只对应一个固定组件。

Theme/Accent 继续决定视觉风格，元素树决定如何组织本页。模型输出结构化数据，不输出可执行 HTML、CSS 或任意脚本。

## 结构与内容分开

正文仍为可编辑的 Markdown，引用和讲者备注沿用现有链路。第一版保留统一的页标题区，程序从标题以下的最终正文生成编号内容块清单，模型只返回引用这些编号的树；树本身不携带新事实、数字或文案。

采用新的 `composed` 内容页类型。这个类型是通用组合渲染器的入口，不是一个新的固定模板。写作允许混合短段落、已有强调、列表、表格、引文和托管图片，内容块之间用空行分开。已有版式继续可用，模型在需要混合表达或特殊空间关系时选择组合式设计；大纲中也可显式选择。

第一版树包含：

- 容器：`row`、`column`，可嵌套，子项比例独立指定。
- 分组：容器可使用无底色、浅色面、强调面或边界；同级对象应有可比的视觉权重。
- 内容叶子：引用一个内容块，选择 `text`、`stat`、`list`、`table`、`quote` 或 `image` 等允许的表现方式，以及字号层级、对齐和支持/强调角色。
- 空间规则：有限的间距、内边距和比例值；不以领域关键词或参考截图中的对象、颜色做判断。

优先完成这些原语的真实组合能力，不把整页版式嵌进小框里假装元素。复杂图表和关系图仍可使用现有专用版式；将其扩为组合原语需要继续遵守现有数值及关系核查规则。

## 生成与保存

在组合页正文经过正常核查后增加 `compose` 步骤。模型读取页面目标、设计说明和准确的内容块清单，一次返回本页元素树。进行结构校验后最多修复一次；失败保留完整正文并记录明确原因，不在每次预览时调用模型。

元素树以版本化的页面元数据保存，与正文一起进入版本、导出、保存重开、主题切换及打印路径。采用独立的 `scene` 注释元数据，避免复制正文或把元素树送入事实核查。内容指纹由程序生成，忽略引用编号变化和讲者备注，不能由模型自行填写。正文实质改变后，旧设计会失效；模型重写/修订会重新构图，手动编辑预览则显示完整正文与需要更新设计的提示。只要求重排构图时也要把当前用户指令送给构图步骤，不能因正文未变而跳过。

接口为 `{version: 1, sourceHash, root}`，正文块是 `{id, type, markdown}`，模型返回的叶子通过 `blockId` 引用正文。结构与指纹都通过校验后才使用树；指纹等待验证期间按原文显示。

内容块切分规则在 Python 与 TypeScript 两端一致并有共享边界样例：标题、空行、代码围栏和讲者备注均需明确处理。所有可见内容块必须被引用恰好一次。引用重编号不会错绑内容；代码围栏中的示例标记不能被当作页面元数据。

## 渲染和检查

渲染器用原生 React/CSS 实现树，保留现有正文和引用组件，颜色来自主题角色。约束树的深度、节点数、分组宽度和允许的属性，拒绝未知引用、重复/遗漏内容、类型不匹配以及未知版本。

第一版以不重叠的嵌套布局为基础。所有元素参与实际尺寸测量，既检查页面边界，也检查组内文字溢出。设计过密时保留字号适配和可见诊断；无法可靠排布时回退完整正文。预览、缩略图、放映、编辑预览和打印使用同一份树，不截断正文来凑画面。

## 验收

1. 用同一份正文生成至少两棵不同的树，展示不同比例、分组与嵌套结构，证明构图来自模型数据。
2. 真实生成链路运行 compose，前端不是只靠手写样例才能显示组合页。
3. 检查中文、英文、长文本、数字限定、引用、列表、表格、引文和图片回退；内容不得遗漏或重复。
4. 检查无效树、过深树、未知块、重复块、遗漏块、陈旧指纹和模型失败，确认保留完整正文并说明状态。
5. 检查保存重开、主题/强调色切换、手动编辑、模型修订和打印路径；旧文稿和 Report 不产生新调用。
6. 运行有意义的解析/校验与链路回归、前后端相关测试、类型检查和构建，再做浏览器实际尺寸与视觉检查。

## 边界

本轮实现由模型组合元素的原生页面渲染，不包含自由拖拽编辑器、任意像素坐标、外部素材搜索或 PPTX 导出。模型仍需判断表达是否恰当；程序能保证结构和内容保真，不能用结构校验替代美学判断。

## 实施记录

已由主代理规划和验收，两个 Luna 子任务分别实现后端生成链路与前端渲染。Slides Skill 版本为 7。组合页的正文正常写作、核查后进入 `compose`；传统生成、工作区写作/编辑/审校及版本修订均已接通。显式重排请求会把当前指令传入构图步骤，即使写作者返回正文不变，也能生成新的树。普通主题切换、核查、已有固定版式和 Report 不增加构图调用。

当前边界为 24 个内容块、40 个树节点、4 层深度；每个分组包含 2–4 个子项，比例值为 1–4。元素支持文字、关键数字、列表、表格、引文、托管图片。标题保持统一标题区。构图通过原生嵌套网格实现，分组比例实际分配宽度和高度。画布与字号预算写入模型指引；程序仍会检测实际排版，不能把结构合法当作一定美观。

`scene` 注释、来源指纹和正文一起保存。正文编辑器隐藏设计数据，只显示可编辑内容；保存时先按原位置和相同内容指纹保留未变页，再匹配移动页面，避免同一正文的不同构图互相替换。修改讲者备注或引用重编号不会失效；实质改文后保留完整正文并提示重新设计。仅重新构图不会把未经核查的正文标记为已核查。

模型验证使用现有 Outputs 模型 DeepSeek Flash，仅发送预先写好的合成内容。两轮共 4 次调用，最后一轮 2 次调用生成了两棵不同的树，正文逐字相同、引用不变，无修复或跳过。它验证真实构图调用及内容保真，不代表完成了真实资料库的整套事实核查。记录见 [model_probe.json](../artifacts/validation/presentation-composer/model_probe.json)。

浏览器验证覆盖 13 个样例 × 4 种主题，包括相同正文的不同树、真实模型输出、混合内容、嵌套色面，以及重复/缺失块、失效指纹、未知版本、损坏元数据和过密内容。正常组合页全部使用组合渲染，原有引用数量一致，无画布溢出；最小适配比例 0.73。极长文本样例会退回原文并提示拆分，原始内容保留在编辑器中，不保证任何长度都能塞进一页。检查了主预览与缩略图的字号和引用一致性、实际放映、打印 DOM，以及编辑讲者备注后五页设计的保留。缺失图片显示原始说明占位；未逐页检查导出的 PDF，也未用真实图库图片覆盖所有长宽比。

自动验证：前端全量 87 个文件、759 项通过；默认并发运行曾出现超时，限制为 2 个 worker 后通过。收尾改动后的解析、保存、组合渲染、预览和打印定向测试共 72 项通过。后端全量运行 1122 项通过、2 项跳过，另两处旧断言分别因新增版式列表和通用设计指引文本而需要更新；更新后这两项定向测试通过。Ruff、TypeScript、`git diff --check` 和最终生产构建通过。构建保留已有的主包超过 600 kB 提示。

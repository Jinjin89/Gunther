# 流式听写与 Option＋空格快捷输入实现手册

状态：实现与验收手册，2026-10-28。两个听写入口已编码、打包并安装到本机 Gunther，供用户使用最新版继续验证体验。
实现前阅读 [AGENTS.md](../AGENTS.md)。

## 1. 已确认的范围

| 入口 | 使用方式 | 文字去向 |
| --- | --- | --- |
| Gunther 对话框 | 使用现有麦克风入口，边说边显示、更新文字，保持流畅听写。 | 对话输入框中的草稿，发送仍由用户操作。 |
| Mac 全局快捷听写 | Gunther 运行时，在其他应用中按 Option＋空格，屏幕底部弹出小框，开始听写并实时显示文字。 | 停止并收齐最终文字后，自动复制到系统剪贴板，由用户自行粘贴。 |

全局入口的完成动作是自动复制到剪贴板，不自动粘贴、不模拟键盘输入，也不自动发送消息。

不读取屏幕、选中文字、其他应用内容或外部输入位置，不增加“当前状态识别”功能。
现有 Recorder 不改。可以复用底层音频编码和流式协议，但不改它的界面、录音流程、设置或存储行为。

## 2. 预期体验

### 对话框

1. 用户通过现有麦克风入口开始听写。
2. 正在说的文字持续出现，并允许识别服务修正尚未确认的句子。
3. 已确认的句子保留下来，新的句子继续显示；同一句修订不能反复追加。
4. 停止时收齐最后一句，保留完整草稿，用户可以修改并决定是否发送。

保留听写前已有的输入内容，流式更新只作用于本次听写对应的文字，不覆盖用户其他草稿。
自动复制这一动作属于全局快捷入口；对话框的结果继续由输入框承接。

### 全局快捷入口

1. 按 Option＋空格，显示屏幕底部的小浮窗并启动听写。
2. 使用简洁的小听写条，只显示必要状态、实时文字和停止操作，不放说明段落或结果确认区。
   拖住听写条上沿可以移动，本次运行中保留移动后的位置，不在每次打开时重新居中。
   浮窗精修为文字优先的浅色/深色样式，移除装饰性波形，仅用实际音量驱动的小标记表示收音。
3. 已有听写进行时，再按 Option＋空格或点停止，立即停止采集并收起浮窗。
4. 最后一句的确认和自动复制在后台完成；不弹主窗口、不重新显示听写条、不要求再点击一次。
5. 用户自行切换到需要的位置粘贴。复制仍以最终确认文字为准，不能为立即收起而提前复制未完成内容。

当前起止交互：按一次 Option＋空格进入；已有听写进行时，再按一次即停止并收起，浮窗停止按钮行为相同。
不增加长按、双击等额外操作模式。成功收尾不需要再点击确认复制。

浮窗使用约 120 ms 原生淡入、100 ms 淡出，不加弹跳或大幅缩放；系统开启“减少动态效果”时直接显隐。
停止采集先于退出动画，识别收尾和剪贴板复制独立在后台完成；快速重新打开会中断上一次退出动画，避免旧定时器关掉新窗口。
这轮外观与动效仅作用于全局听写浮窗，不修改其他页面和听写识别流程。

## 3. 当前代码基础

| 位置 | 当前行为与实现关注点 |
| --- | --- |
| `apps/desktop/src/services/useDictation.ts` | 通过 v2 协议发送 16 kHz PCM，处理临时与最终句子，等待收尾确认后才报告完成。 |
| `apps/desktop/src/services/dictationText.ts` | 按句子 ID 合并修订、忽略重复确认，并保护受控输入框中的人工编辑。 |
| `apps/desktop/src/services/useDictatedField.ts` | 将流式文字更新到现有对话草稿，保留原有文字和人工修改。 |
| `apps/desktop/src/api.ts` 的 `recordingSocketUrl` | 已支持区分听写与录音用途，也能构造 v2 协议地址。 |
| `apps/desktop/src/services/pcm.ts` | 旧协议默认 24 kHz；当前 v2 客户端使用 16 kHz。切换协议时必须同步检查实际编码采样率。 |
| `apps/backend/gunther/api.py` 的 `/recordings/live` | 桌面听写传入 `purpose=dictation&protocol=2&stream=true`，仅对本次听写请求开启流式，不修改已保存的模型或录音设置。 |
| `apps/backend/gunther/realtime.py` | 已提供临时/最终 `transcript.piece` 事件以及收尾完成事件 `transcript.flushed`。 |
| `apps/backend/gunther/speech_registry.py` | 保留历史角色配置及旧客户端行为；桌面客户端显式请求实时听写。 |
| `apps/desktop/src/shortcuts/shortcuts.ts` | 保留应用内 ⌘⇧M，并显示 macOS 全局 Option＋空格快捷键说明。 |
| `apps/desktop/src/dictation/` | 独立底部浮窗，复用听写会话，完成后自动调用系统剪贴板写入。 |
| `apps/desktop/src-tauri/src/dictation_shell.rs` | 注册 macOS 全局快捷键，防止按键自动重复，管理浮窗及仅向剪贴板写入文本的原生命令。 |

此次修改保留音频分块传输，补齐了听写请求的流式模式、临时文字更新和收尾确认。
历史 `dictation.stream=false` 不需要用户手动修改；新桌面请求显式开启实时识别，旧客户端和 Recorder 沿用原行为。

`docs/LIVE_TRANSCRIPT_PLAN.md` 描述的是已有 Recorder 方案，只作底层能力参考。本次不执行其中的 Recorder 改造阶段。

## 4. 建议实现顺序

### 第一步：接通听写的实时文本

- 保留用户已经选择的听写服务和模型，处理听写角色的流式模式。
- 同时考虑默认值和已保存的 `dictation.stream=false`；只改默认值不会改变已有配置的实际行为。
- 调整范围仅限听写路径，不更改 Recording 角色或重置其他语音设置。
- 复用已有 v2 协议和音频编码函数，保证请求声明的采样率与实际发送的数据一致。
- 临时与最终文字按事件 ID 更新。同一临时结果被修订时替换原有文本，不当作新句子追加；最终结果只提交一次。
- 用“已确认文字＋当前临时文字”组成实时预览。不要用逐字动画假装识别服务返回了流式结果。
- 服务只支持分段结果时，保留实际能力并准确报告状态；本次不增加其他识别供应商或模型选择步骤。

共享的是听写会话和文本更新能力，不复制整个 Recorder 组件，也不把它的复听、段落整理或录音持久化流程接入短时听写。

### 第二步：接入现有对话输入框

- 将实时文本状态接入现有听写 Hook 和使用它的对话输入框。
- 保留已有麦克风按钮和应用内快捷键入口。
- 区分原有草稿、用户修改的内容与当前识别服务可以修订的部分，避免流式回包覆盖人工输入。
- 录音开始、停止和最终文字到达不应自动触发消息发送。
- 确认各现有对话入口都能使用同一套流式听写行为，避免只修改某一个页面。

### 第三步：增加 Mac 全局快捷键和底部浮窗

- 在原生层注册 Option＋空格，使 Gunther 在后台运行、其他应用位于前台时仍能响应。
- 创建轻量听写浮窗，位于屏幕底部；不要通过打开主窗口或 Capture 窗口来替代。
- 浮窗复用前两步的听写能力。它只承载本次转写文字、必要状态和停止操作。
- 防止按键自动重复或多次触发创建多个听写会话、多个浮窗。
- 快捷键注册失败应准确提示，不静默改成另一个快捷键。
- 更新相应窗口与权限配置，复用已有后端鉴权连接；不要引入屏幕读取或外部应用控制。
- 浮窗关闭、组件卸载和会话终止时，释放本次麦克风、音频处理和 WebSocket 资源；旧会话的回包不能污染下一次听写。
- 不得为了启动听写而暂停或关闭现有 Recorder。

### 第四步：停止、收尾和自动复制

正常流程应为：

`开始连接 → 听写中 → 停止采集 → 等待最终结果 → 自动复制 → 已复制`

窗口显示与该流程分开：停止采集时立即隐藏，收尾与复制继续在后台完成。完成事件不得重新显示或聚焦任何窗口。
开始时先采集并缓存音频，不等待识别服务握手才显示听写状态。

- 停止采集后向服务提交收尾请求，等待已发送音频对应的最终结果和完成事件。
- 不要在点击停止的瞬间复制临时文字，也不要在最终一句到达前关闭连接。
- 识别服务完成本次音频后，直接使用其返回的最新文字；不再增加“每一句是否确认”的拦截，不做二次校验、润色或重写。
- 保留必要的网络错误和超时处理，不把连接问题描述成文字未通过检查。
- 全局入口在后台成功收尾后自动写入系统剪贴板，不显示额外的成功确认窗口。
- 在真实 Mac 桌面包中验证剪贴板写入，不只验证浏览器开发环境；需要原生接入时保持封装简洁。
- 空文本不覆盖原有剪贴板。识别或复制失败时保留已有文字，明确显示失败，不误报成功。
- 后台旧事件或重复的完成事件不能再次复制、覆盖用户之后放入剪贴板的内容。

## 5. 验收清单

| 场景 | 应观察到的结果 |
| --- | --- |
| 对话框持续说一段话 | 录音未停止前已经出现文字，临时句子持续更新。 |
| 同一句收到多个修订或重复事件 | 原位更新，最终文本不重复。 |
| 输入框已有文字，期间也有人工修改 | 原有草稿和用户修改不被后续识别结果覆盖。 |
| 说完立即停止 | 最后一句完整到达后再结束；不漏掉尾部文字。 |
| 在其他应用中按 Option＋空格 | 底部出现听写小浮窗，Gunther 主窗口无需先切到前台。 |
| 全局听写正常停止 | 最终文字自动进入剪贴板，用户手动粘贴后得到完整文本。 |
| 使用全局听写的整个过程 | 不自动粘贴到其他应用，不自动发送消息，不读取屏幕或外部应用内容。 |
| 无语音、服务出错或收尾超时 | 不覆盖剪贴板、不误报完整成功，已有文字可以查看。 |
| 连续多次开始/停止、关闭后重新打开 | 无重复会话、重复文本或旧会话回包，麦克风资源正常释放。 |
| Recorder 已有录音或草稿 | 现有 Recorder 行为和数据保持原样，不被听写入口重置。 |

测试重点是临时/最终文本合并、收尾完成信号、受控输入框草稿保护、全局快捷键生命周期和剪贴板写入。
后端协议有改动时，回归现有 `test_speech.py`、`test_realtime_stream.py`；编码或共享文本处理有改动时，回归对应测试。
原生快捷键与浮窗需要构建并启动 Mac 桌面包实际验证，单独的前端测试不能证明跨应用快捷键已生效。

验证使用独立的测试文本、音频和临时目录，保护真实库，尤其是 Leadership；不创建数据备份。

# 演示文稿逐页内容设计

2026-10-17。承接 `PRESENTATION_QUALITY_PLAN_CN.md` 的主题工作。用户明确要求保留 Theme，进一步改善每一页如何组织内容、选择视觉表达、使用对比与流程图。本次聚焦 Slides。

## 判断

当前规划器给每页标题、目标、版式和衔接，写作者随后直接填正文。13 个版式提供了基本绘制能力，但缺少独立的页面设计决策。`flow` 只有线性编号步骤，没有分支和带语义的连线。Theme 只能改变同一构图的字体和颜色。

本次将流程扩展为：理解与收集材料 → 大纲 → 逐页内容设计 → 撰写与绘制 → 事实核查、编辑和读者审校。页面设计决定如何解释现有内容，不是新增证据。

## 本次实现

### 1. 独立的 design 阶段

Slides 技能增加 `design` 阶段，在大纲确定后、写正文前调用。一次设计整套大纲，避免每页都增加一次模型调用。输入包括受众/用途、整套大纲、材料卡片与可用图片。输出只能修改允许的版式和页面设计，不能重排或删除大纲，不能自行改变标题、材料引用或事实。

每页保留以下设计说明：

- `intent`：观众看完本页应理解什么，和已有论点一致。
- `visual`：如何用图形、比较或其他形式说明它，为什么适合这些材料。
- `composition`：`standard`、`split`、`spotlight`。只允许用于实现支持的版式。
- `emphasis`：值得在现有内容中强调的对象或短语；写作者据此安排加粗、图表重点等。
- `notes`：不挤进画面的解释、限定条件和过渡应如何放入讲者备注。

设计说明作为可编辑计划，不直接当作有来源的正文。新增的图形关系仍必须在正文中引用来源并经核查。

设计调用有固定边界。模型出错、漏页或返回不支持的方案时保留可用原大纲并记录 design 阶段未完成，不虚构已经设计成功。旧稿没有设计字段时仍用已有构图。

### 2. 构图与主次

- `standard`：保留现有布局，适合表格、图表、流程等需要较大展示空间的内容。
- `split`：标题/简短说明与主要视觉分区，优先支持大数字、原始图片和引文。
- `spotlight`：放大一个关键元素，优先支持大数字、引文和短文字。适配范围用代码统一约束，不能给任意复杂表格套用。

构图以代码生成的页级标记保存，例如 `<!-- layout: quote; composition: split -->`。主题与强调色切换保留构图；生成、修订、保存重开、大纲重建、编辑预览、放映和打印都读取它。未知构图安全回退标准版式，不漏正文和引用。

强调使用 Theme 的色彩角色及清楚的层级，不能把风险、因果或优劣仅通过装饰颜色暗示成事实。不为追求每页不同而制造比较或流程。

### 3. 有证据的关系图

新增 `diagram` 版式，用一张 Markdown 关系表表达图形，模型不输出可执行 HTML/SVG。每行是一个完整关系：起点、关系/条件、终点；引用放在关系单元中。节点名称保持一致，不能用排序推测边。

示例仅说明格式，不是生产规则：

```markdown
| From | Relationship | To |
| --- | --- | --- |
| 收集材料 | 完成收集后 [1] | 检查材料 |
| 检查材料 | 材料完整 [1] | 开始分析 |
| 检查材料 | 仍有缺失 [1] | 补充信息 |
```

渲染器以代码原生节点、正交连线、方向箭头和可点击引用画出关系。第一版支持小型有向无环图（2–6 节点、1–8 条边；层数/每层节点数按实际画布能力限制），明确适用于分支流程、依赖与层级。线性流程继续可用现有 `flow`。不把并列内容画成因果关系。

无效表、循环、过多节点/边、不能清楚排布或引用缺失时请求修正或回退为完整表格/文字，并说明限制，不能删除节点或边来凑图。前后端共享格式约定并用相同边界样例验证。图中的事实和连线含义沿用核查流程。

### 4. 创作界面与持久化

在大纲编辑器中展示可折叠的“页面设计”，允许修改设计说明与兼容构图。生成过程显示 Designing slides。`Planned`、`OutlineItem`、工作区条目、输出事件、版本保存、导入/重建以及写作/审校提示贯通这些字段。

自动规划可以重新建议版式；用户编辑过的大纲与设计优先。新增单页也能获得设计，局部文字修改不重新设计整套文稿。设计字段改变后，相关页面应按现有过期机制重新生成，不把旧页面标为已经应用新设计。

## 验收

- 真实调用链中 design 位于大纲之后、写作之前，传统 build 与对话式生成都能走到；报告无额外设计调用。
- 每页设计字段到达写作者/编辑，保存重开不丢失；只改一页时其余页面保留原文。
- 构图确实改变空间安排；Theme、Accent、正文修订互相不丢 metadata。
- 关系图节点和连线来自表格，关系标签与引用保留；不同语言、分支、长标签和非法图都有测试。
- 至少展示标准/左右分区/重点突出和分支图的实际浏览器画面，检查深浅 Theme、缩略图与打印路径。
- 运行相关 Python/TypeScript 测试、Ruff、类型检查、构建；必要时跑全量回归。后端全量测试需要允许 127.0.0.1 测试服务，避免沙箱端口限制误报。

## 边界

本次不是自由拖拽画布，也不是可编辑 PPTX 导出。第一版关系图不支持任意大图或循环图。自动设计不能证明美学或叙事质量，实际效果需用真实材料继续评估；失败与回退必须可见。

## 实施与验证记录

本轮逐页内容设计已实现。Slides 技能现在可在大纲后以一次有界的整套调用生成逐页设计；结构校验保留大纲标题、顺序、引用和有效布局，锁定的用户选择优先。失败或不完整响应会记录为跳过并保留原计划；同一失败计划在写作分块时不会重复调用。报告流程不增加设计步骤。设计字段、锁定/尝试状态和关系衔接贯通 API、工作区、导入、重建、修订、事件和 Outline 编辑器，编辑提示能读取已确认的关系。旧式显式布局请求仍按用户选择处理。

每页构图通过独立的 `composition` 标记保存，兼容性按布局约束；标准、左右分区和重点突出会改变空间安排。新增 `diagram` 表格格式，以受限 DAG 生成带方向、标签及引用的节点图。前后端共同检查节点/边数量、循环、层级/宽度、标签长度与引用。无法安全绘制或关系未获支持时保留完整关系表及引用并记下回退原因。设计说明作为可编辑折叠项呈现在大纲中，不作为正文证据；写作规则也明确区分讲述指示与来源支持的事实。

自动生成的设计说明不保留素材池中的临时引用编号，避免正文保存时重新编号后指向错误来源；正式证据绑定仍在大纲的 refs/cards 中。用户编辑的设计文字及原始材料不经过这项清理。关系核查检查的是条件、方向和概念含义，允许忠实缩写节点文字；不会要求来源本身已经画出节点或箭头，也不会仅因两个对象都出现在原文就认可它们之间的关系。

真实模型的小规模验证使用现有 Outputs 模型 DeepSeek Flash 和纯合成材料：六页设计生成成功，分支图经正常版式修正缩短标签后，两条条件关系获得 supported 判定并保留 diagram 布局。记录与测试来源见 [model_probe.json](../artifacts/validation/presentation-content-design/model_probe.json)。该记录不是对完整模型输出的盲评，也不将页面上所有句子视为已经验证的事实。

最终自动验证：完整前端测试 85 个文件、745 项通过；完整后端测试 1108 项通过、2 项跳过。Ruff、TypeScript 类型检查、`git diff --check` 与生产构建通过。构建仍有应用主包超过 600 kB 的体积提示。

浏览器验收覆盖四种主题下的 13 个内容样例，包括真实模型生成页。页面均未超出画布，最小字号适配比例 0.85；循环、过深、长标签和无引用关系保留为完整表格。检查了打印 DOM 的主题/构图传递、可点击的图中引用，以及隐藏重复焦点项。图中有效关系通过模型覆盖检查。未另行逐页检查导出的 PDF 文件。

限制：图形仅支持受限小型有向无环关系；自动设计仍是布局建议，不能证明内容组织适合所有材料。浏览器视觉覆盖是合成案例，具体用户材料仍需人工审阅。

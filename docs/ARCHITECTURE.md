# Architecture

Gunther keeps one workspace on the computer running the Python service. The desktop and phone act through its API. SQLite holds durable records and references to managed files. Library folders give a readable view of that workspace.

## Processes and boundaries

- **Desktop.** Tauri owns the backend Helper, windows, tray, shortcuts and private local files. React uses the TypeScript shapes in [packages/contracts](../packages/contracts/) and the HTTP and stream readers in [apps/desktop/src](../apps/desktop/src/). The packaged Helper listens on loopback and uses a per-launch token and Origin checks.
- **Mobile.** Flutter uses the same API through a scoped HTTPS gateway after pairing. Device credentials and trust material live in secure storage. The phone persists captures in an outbox until the workspace acknowledges them.
- **Backend.** [main.py](../apps/backend/gunther/main.py) creates the FastAPI app, wires providers and workers, and owns app middleware and lifetime. [api.py](../apps/backend/gunther/api.py) mounts the job routers in route order. [service.py](../apps/backend/gunther/service.py) wires the domain operations to one `KnowledgeService` instance. Routes parse and authorize requests, then call those operations.

## Data flow

1. Capture registers a note or source, or stages and verifies an original first. File receipts identify the queued job. The worker claims a lease, reads and indexes the file, and publishes a revision only if its expected head and lease still match. Originals and their evidence links remain available.
2. Search and Ask resolve eligible material. The library stores the selection separately from row placement and chat history. Library Chat sends its shared Sources selection and clears section focus on every turn, including retries. Retrieval verifies a pinned revision before reading any cached passage from it. An answer stores numbered evidence snapshots with the turn and queues a key results job when it cites a library source. An empty Chat requests a library overview through the leased Analysis queue. It has one job per library, and its result is published with job completion after checking the source fingerprint again.
3. Studio builds use the library's current source selection. A targeted refinement uses the lineage head's stored scope or an explicit refinement scope stored with that lineage in the conversation. The output binds its material, builds or edits the work, checks the claims and stages a candidate version. The version commit owns the seal, lineage head and associated conversation writes. Opening a saved version verifies its seal before projecting sections and checks.
4. Live audio and durable recording uploads use separate transports. Recording completion uses the server byte ledger and checkpoint.

Ask and Outputs share the run registry for Stop and Follow. Their completion events follow the durable save and Activity update. A library Activity link opens the workspace with the linked chat, run or version in the middle when the link carries a target. Output keys identify a conversation, or a lineage for an unattached restyle or visual review. Studio shares a process-wide pool of 12 workers across builds for fan-out such as reading long material, checking parts and designing slides. Each call keeps its own worker limit. Calls made from a Studio worker run inline. Ask runs independently of this pool. [Run registry](../apps/backend/gunther/answer_runs.py) · [Studio requests](../apps/backend/gunther/studio/requests.py)

## Storage

Ask commits a turn's source selection and section focus before answering. Model and web calls in Ask, Studio, and Analysis run after the sessions that prepared their inputs have closed. Retrieval opens read sessions as needed during a run. Final messages, output versions, and Analysis results are published in short write transactions.

The Analysis lane claims durable key results jobs by origin. The database allows one running job per library. The worker reads the saved claim and original passage material, closes the session, then calls Analysis and the Checker. It checks ownership again before publishing sentences, evidence and job completion in one transaction. Undo uses each row's origin to keep contributions from earlier jobs.

Distillation searches for related sentences within the library and with overlapping sources. Full-text indexing commits with kept results. When local embeddings are available, the local processing lane encodes kept sentences outside the write transaction, then checks that they are still kept before storing their vectors. Removed sentences can inform deduplication and stay out of both indexes. The API, deduplication and the library folder share the same evidence eligibility check. Permanent source deletion drops the affected groups and their index entries. Kept sentences with other evidence groups are indexed again.

Ask and Studio use the same key result lookup in a read session. It applies library, source and passage scope before ranking kept results. Both pools deduplicate original readings by source, revision and block. The orientation block is rendered after numbering and refers to complete evidence groups present in the pool. Rebuild resolves the scope from the output's lineage, including legacy saved answers listed in that scope.

Trash marks all versions of an output lineage in one transaction. Conversation batches use ownership from the sealed version provenance. The run registry guards those writes against active turns. Permanent deletion removes versions leaf-first, then their conversations, and releases files after commit once the last reference is gone. [Trash service](../apps/backend/gunther/trash.py)

- [models.py](../apps/backend/gunther/models.py) contains the SQLite records. [database.py](../apps/backend/gunther/database.py) enables WAL and foreign keys. [migrations.py](../apps/backend/gunther/migrations.py) applies ordered migrations at startup.
- A source has original capture provenance and immutable reading revisions, including ordered elements and indexed passages. The head selects the current reading. The source paper card and search index are derived. Figures and citations carry source, revision and region identity.
- A library root has readable folders and a private `.gunther/` directory for the database, originals and recovery state. The desktop config directory holds private preferences and provider keys. See [Library folders](LIBRARY.md#library-folders) and [Operations](OPERATIONS.md#data-and-logs).

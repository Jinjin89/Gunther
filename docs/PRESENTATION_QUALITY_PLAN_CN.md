# 演示文稿专业化：研究与实施计划

研究日期：2026-10-17。范围：Gunther 的 Slides 创作与呈现。用户已确认本次聚焦 PPT / PowerPoint，Report 暂不纳入实现。此文档区分本次实施和后续路线，后续能力不能描述成已经完成。

## 结论

Gunther 已有材料理解、大纲、13 种版式、引用核查和编辑/读者审校。下一步应在这些能力上补全可选择的视觉风格、可传递的页间关系和真实渲染检查。风格控制外观，故事结构控制内容顺序，演讲/阅读用途控制密度，三者应独立。

## 研究依据

| 观察 | 来源 | 对 Gunther 的启示 |
| --- | --- | --- |
| Gamma 的官方流程先整理需求和大纲，也允许保留内容后更换视觉方向 | [Gamma 创建流程](https://help.gamma.app/en/articles/15002203-how-do-i-create-with-agent-in-gamma) | 保留现有对话入口与大纲编辑；更换视觉风格不应重新生成事实 |
| PowerPoint 主题协调色彩、背景、字体与占位符 | [PowerPoint Themes](https://support.microsoft.com/en-us/powerpoint/training/add-color-and-design-to-your-slides-with-themes) | Style 应覆盖成套设计属性，现有 Accent 只是其中一项 |
| Microsoft 建议为不同内容场景设计有区别的布局，测试长短文本、对比度与边界 | [Designer 模板指南](https://support.microsoft.com/en-au/powerpoint/creating-custom-templates-that-work-well-with-designer-in-powerpoint) | 复用已有内容布局，加入风格变体与跨布局视觉验收 |

以上为产品官方说明，不是对竞品输出质量的独立测评。本文方案是结合这些说明和本地代码形成的工程判断。

## 当前代码诊断

- `apps/backend/gunther/skills/slides/` 已具备故事结构与版式方法，`skill_runner.py` 已有编辑和读者检查；不另起一套创作流水线。
- `skill_runner.SHAPES["slides"]` 明确要求 `link is empty`，虽已有通用 `Planned.link`，却没有让幻灯片使用页间关系。写作大纲文本也没有传入这条关系。
- `apps/desktop/src/outputs/slides/accent.ts` 只有六种强调色，默认白纸黑字；字体和页面构图没有可选的完整风格。
- `SlideFace.tsx` 是预览、缩略图、放映和打印的共同绘制入口，适合统一接入主题。`slideFit.ts` 的缓存目前按内容而非主题区分，换字体/留白后可能沿用错误字号。
- 页面会缩小内容直到 0.55 倍，极端内容仍可能超出页面，缺少给用户的明确诊断。
- 当前实际导出为 Markdown 和打印到 PDF；仓库存在 PPTX 样本不代表产品具有可编辑 PPTX 导出能力。

## 产品设计

保留内容布局和引用。Style 独立于报告的 `style`（文章结构），采用 `theme` 名称避免混淆。

| 风格 | 适用场景 | 外观方向 |
| --- | --- | --- |
| Classic / 经典 | 兼容已有文稿、学术阅读 | 白底、清楚层级、原有克制风格 |
| Briefing / 商务简报 | 项目汇报、决策讨论 | 无衬线字体、冷色强调、明确标题与数据层级 |
| Editorial / 编辑式 | 研究解读、内容分享 | 暖白纸色、衬线标题、较舒展的留白 |
| Keynote / 深色演讲 | 大屏演示、短时分享 | 深色底、高对比文字、突出主信息 |

不同风格不规定材料必须具备哪些章节，也不增加虚构事实、数字或图片。风格切换只改变呈现；原有引用、备注和后续页内容应保持原样。旧文稿没有主题时继续显示 Classic。

## 本次实施：第一阶段

由主代理负责研究、设计和验收；由用户指定的 Luna 子代理写代码。先形成可操作、可保存的风格选择，沿用已有版本编辑机制。

1. **主题数据与兼容性**：在已有标题页布局标记中增加可选主题，前后端一致解析。颜色切换保留主题，主题切换保留颜色和正文。写作修订、保存与重开不能丢主题。遇到未知主题安全回退。
2. **风格选择与统一绘制**：在 Slides 工具栏提供带视觉样本的 Style 选择；选择后创建可恢复版本。主题控制字体、纸色、墨色、强调色、留白和适当的封面/标题处理。预览、缩略图、Present、编辑预览和打印使用同一入口。
3. **故事衔接**：规划时明确每页承接上页的关系，并将关系传给逐页写作与审校。增加有限、可解释的机械检查，例如重复标题、缺失衔接；不能把机械检查通过说成逻辑已经正确。旧大纲继续可读。
4. **可读性反馈**：字体适配缓存纳入主题；当前页过密、需要明显缩字或仍溢出时提示用户拆页、精简或移入讲者备注，不自动删内容。
5. **验证与文档**：验证主题与颜色组合、旧标记兼容、修订保持、跨视图一致、叙事提示传递、长中文与图表渲染。运行相关前后端测试、类型检查与构建，实际查看浏览器渲染。

第一阶段的选择入口在已有幻灯片的创作/预览工具栏。生成前的偏好面板需要完整贯穿对话、生成请求和来源记录，留在下一阶段实现，避免只拼接一句提示词却无法可靠保存。

## 验收条件

- 四种主题能选择、保存和重开，视觉区别包括字体/背景/层级，不能仅换一个颜色。
- 主题/Accent 切换不改事实文字、引用和备注；已有标记与没有标记的旧文稿仍能使用。
- 所有幻灯片入口和打印读取同一个主题，字体计算不会跨主题串用。
- 新规划包含页间关系，写作收到它；缺失或重复问题可解释且会记录，不能悄悄伪造衔接内容。
- 常见图表、表格、流程、中文和长标题实际渲染可读；无法容纳的极端内容有提示。
- 不触碰本次任务开始前已有的未跟踪文件：`ArtifactStudio.tsx`、`apps/desktop/preview/`、`__workspace_review.html`。

## 后续路线（本次不实施）

1. **生成前设计简报**：受众、演讲/阅读、时长、Style 独立设置；模型建议可覆盖，用户明确选择优先。Report 共用色彩与排版基础，同时保留纸张阅读的独立布局。
2. **可编辑 PPTX 导出**：引入结构化页面描述，将文字、表格、图表和备注映射到原生 PowerPoint 对象；明确网页字体与 Office 字体差异，验收真实 Office/LibreOffice 输出。不能把整页截图冒充可编辑 PPTX。
3. **品牌与参考模板**：导入字体、色彩、Logo、页面母版，先预览再应用；引用内容和视觉资产分别管理。
4. **质量评估集**：使用不同语言、材料类型和密度的样本，进行匿名盲评，分别评估故事连贯、可读性、事实忠实、视觉完成度和修改成本。记录生成耗时与额外审校成本。

## 实施记录

第一阶段实现于 2026-10-17：

- 在标题页标记中加入可选 `theme`（classic、briefing、editorial、keynote），前后端解析一致；Accent 与主题独立保留，缺省/未知主题回退 Classic。手动改版、标题重写、活动工作重开、整体重规划和继承父版本的重建均保留主题。
- Slides 工具栏提供 2×2 小样式选择器；应用选择会经现有编辑接口保存为新版本。`SlideFace` 为预览、缩略图、Present、编辑预览与打印提供主题纸色、文字、字体、强调色和间距。Keynote 在画面、控制、数据轴和强调标记上使用深色适配颜色。
- 字号适配缓存纳入主题。预览页检查缩字和实际溢出（包含缩放后的页面边界与不可断开的长字符串），在幻灯片外显示精简建议；导出页面不包含诊断文案。
- 大纲页间 `link` 已传入逐页写作和编辑提示；Outline 编辑器可查看/修改衔接。输出接口、版本存储和活动工作导入/重建都会保留它。规划与最终检查记录缺失页间关系、重复标题，发现只作为待人工判断的提示。
- 自动验证：完整前端测试 85 个文件、736 项通过；此后新增的样式保存、历史版本禁用、打印主题与默认样式不重复保存测试另行通过定向运行。完整后端测试 1099 项通过、2 项跳过。后端首次全量运行因沙箱禁止绑定本机端口而中断，允许回环测试服务后全量通过。Ruff、TypeScript 检查与生产构建通过；构建仍有现有应用主包超过 600 kB 的提示。
- 视觉验收：主代理在真实浏览器检查了四种主题、13 种既有布局构成的 18 个样本。常规内容、长中文标题和负值图表没有画布溢出；刻意设置的过长正文与不可断长串会显示溢出提示。检查了 1280×900 与 900×700 窗口的选择器、深色导航与图表标记、Escape 焦点返回、Present 背景，以及打印 DOM 与屏幕主题一致性。

限制：自动标题/衔接检查只能发现完全重复标题和空的衔接字段，不能证明故事逻辑正确；本次没有开展真实模型输出的盲评。打印仍使用浏览器打印到 PDF，已验证主题传递与打印样式，未另行逐页检查导出的 PDF 文件。本次没有实现可编辑 PPTX。
